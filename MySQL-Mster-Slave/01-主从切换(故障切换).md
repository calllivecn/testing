# 主从切换


在MySQL 8.0中使用全局事务标识符（GTID，Global Transaction Identifier）模式进行主从复制时，可以实现更简单且更可靠的故障转移机制。当主服务器发生故障时，可以将一个从服务器提升为主服务器，因为GTID能保证所有已提交的事务都已被所有从服务器复制。

以下是在默认的MySQL 8.0一主一从配置中，使用GTID_MODE=ON时主动触发故障切换的具体操作过程：

1. **确认主服务器状态**：
   首先检查主服务器的状态，如果它确实不可用或者你决定将它下线进行维护，那么可以考虑进行故障切换。

2. **停止从服务器的复制**：
   在准备将从服务器提升为主服务器之前，需要先停止从服务器上的复制。这可以通过执行以下命令完成：

   ```sql
   STOP SLAVE;
   ```

3. **检查从服务器的GTID状态**：
   查看从服务器是否已经复制了所有来自原主服务器的事务，这可以通过执行以下命令检查：

   ```sql
   SHOW SLAVE STATUS\G;
   ```

   寻找 `Retrieved_Gtid_Set` (之前为：Last_Retrieved_Gtid_Set)和 `Executed_Gtid_Set` 的值，这两个值应该相同，这意味着从服务器已经完全复制了所有事务。

4. **将从服务器提升为主服务器**：
   一旦确定从服务器已经完全复制了所有事务，就可以将其提升为主服务器。这一步骤涉及到更新应用程序的连接信息，使其指向新的主服务器。

5. **清理旧的复制信息**（可选）：
   为了防止混淆，可以清除从服务器上的复制信息，使其不再尝试连接到原来的主服务器。不过，在GTID模式下，这一步骤不是必需的，因为GTID能够自动处理复制的连续性。

6. **重启复制**（如果需要）：
   如果你需要设置新的从服务器来复制这个新的主服务器，你可以在新主服务器上执行以下命令来创建复制用户，并将相应的权限授予该用户：

   ```sql
   GRANT REPLICATION SLAVE ON *.* TO 'replication_user'@'%' IDENTIFIED BY 'password';
   ```

   然后，在新的从服务器上配置复制，并启动复制进程。在GTID模式下，你只需要指定新的主服务器的地址和复制用户信息，不需要指定具体的二进制日志文件和位置，因为GTID会自动处理这些细节。

7. **更新应用程序**：
   最后，你需要更新你的应用程序，使其指向新的主服务器。这可能涉及到修改DNS记录、数据库连接字符串或其他配置文件。

请注意，实际操作中可能还需要考虑其他因素，例如通知应用程序进行故障转移、调整负载均衡器或代理服务器的设置，以及监控切换后的性能和复制状态。在进行故障转移前，建议对整个过程进行测试，以确保一切都能按预期工作。
