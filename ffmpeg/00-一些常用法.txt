# 收集的 ffmpeg 一些用法

- 1 每个轨道分别指定 titile 分别修改音轨-字幕轨的

ffmpeg -i 001.mkv -i /tmp/zx-2.ass -map 0:v -vcodec copy -metadata:g title="第001集" -map 0:a:1 -acodec copy -map 1:s,0:s -scodec copy -metadata:s:a:0 title="日语原版" -metadata:s:s:0 title="简体中文" 001-4.mkv

# ~~-metadata:s:a:0 这里没搞清楚, 这样也可以 -metadata:s:s:0~~
# 这里的 :a 和 :s 好像分别是 音轨 和 字幕轨。 :0 估计是输出文件

-disposition:a:0 default 设置输出文件默认音频
-disposition:s:0 default 设置输出文件默认字幕

- 2 关键帧无损视频分割剪切 与 合并

## 手动选择每个分割的时间点
ffmpeg -i "In.mp4" -f segment -segment_times 00:00:06.165,00:00:14.293 -c copy -map 0 "Out_%04d.mp4"

## 按时间段分割
ffmpeg -i "In.mp4" -f segment -segment_time 00:00:05.000 -c copy -map 0 "Out_%04d.mp4"

## 分段并使用时间戳做为文件名
ffmpeg -hide_banner -rtsp_transport tcp -i "${VIDEO}" -vcodec copy -acodec copy -strftime 1 -reset_timestamps 1 -f segment -segment_time $[30*60] "output-%Y%m%d%H%M%S.mkv"

## 合并 
ffmpeg -f concat -i list.txt -c copy Out.mp4

list.txt:
file '00.mp4'
file '01.mp4'
file '02.mp4'

## 无损压缩

- libx265

ffmpeg -i input.mp4 -c:v libx265 -x265-params lossless=1 -c:a copy output.mp4

- hevc_nvenc

```python
ffmpeg_command = [
    'ffmpeg',
    '-hwaccel', 'cuda',  # 启用CUDA硬件加速
    '-hwaccel_output_format', 'cuda',  # 指定硬件加速的输出格式
    '-c:v', 'h264_cuvid',  # 使用NVIDIA的硬件解码器进行H.264解码
    '-i', input_file,  # 输入文件
    '-vf', 'scale_cuda=1280:720',  # 使用NVIDIA硬件加速进行分辨率缩放
    '-c:v', 'hevc_nvenc',  # 使用NVIDIA的硬件编码器进行HEVC编码
    '-preset', 'slow',  # 编码预设，较慢的速度通常意味着更好的压缩，提高输出质量
    '-rc', 'vbr',  # 可变比特率控制
    '-cq', '0',  # 设置恒定质量因子为0以启用无损模式
    '-b:v', '0',  # 平均比特率设置为0，因为我们在使用恒定质量模式
    '-c:a', 'copy',  # 音频复制，不转码
    output_file  # 输出文件
]
```
注意在上述脚本中，-cq 0 是用来指定无损模式的，而在hevc_nvenc中，这表示启用无损压缩2。

另外，如果你希望使用HM（HEVC Test Model）工具来进行无损压缩，可以通过命令行参数--TransquantBypassEnable=1和--CUTransquantBypassFlagForce=1来实现


## 需要在画面质量和源视频一样的前提下。尽可能的减小文件大小

```shell
ffmpeg -i A.mp4 \
       -map 0 \
       -c:v libx265 \
       -crf 24 \
       -preset slow \
       -c:a copy \
       A.mkv
```

-crf 24: 这是 最核心的参数。

CRF 代表 Constant Rate Factor (恒定速率因子)。这是一种控制视频质量的模式。它不会去适配某个特定的比特率，而是尝试在整个视频中维持一个恒定的“感知质量”。编码器会根据画面的复杂度动态调整比特率：对于复杂的动态画面（如爆炸、水花），分配更高的比特率；对于静态画面（如风景、对话），分配更低的比特率。

这完美符合你的需求：“保持画面质量”。

对于 libx265，CRF 的取值范围是 0-51，数值越小，质量越高，文件越大。

0 是无损的（但文件巨大，通常没必要）。

~18 通常被认为是视觉上几乎无损的。

22-28 是一个非常常用的范围，能在质量和文件大小之间取得极佳的平衡。24 是一个非常可靠的、质量不错的起点。

-preset slow: 这个参数控制编码速度和压缩效率的平衡。

可用的预设包括 ultrafast, superfast, veryfast, faster, fast, medium (默认), slow, slower, veryslow。

preset 越慢，编码器就会花费越多的时间去分析视频帧，寻找更好的压缩方法。这意味着在 相同的CRF值（即相同的质量）下，使用更慢的 preset 会得到更小的文件。
