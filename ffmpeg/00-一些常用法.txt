## 使用QSV

- 依赖非开源驱动库：intel-media-va-driver-non-free
- 常见的linux发行版中默认是：intel-media-va-driver 会少 HEVC 之类的编码支持

- QSV 使用的编解码器名字：

```text
编码：h264_qsv、hevc_qsv、mpeg2_qsv、vp9_qsv（取决于硬件和驱动）

调用方式：QSV 不像 VAAPI 那样要 -vaapi_device，它只需要 -hwaccel qsv，然后直接指定 QSV 解码器或编码器。
```


### 📌 注意事项：

- QSV 在 ffmpeg 编译时必须带 --enable-libmfx 或 --enable-onevpl，否则命令不可用。

- 比 VAAPI 更适合转码场景，因为 QSV 支持 zero-copy pipeline（解码后直接交给编码，不走系统内存）。

- 在 vainfo 看不到 QSV 的支持，因为它不是 VAAPI，而是 MediaSDK / oneVPL 的接口。

```shell
# 示例 1：QSV 解码 + 丢弃输出（测试解码是否成功）
ffmpeg -hwaccel qsv -c:v h264_qsv -i input.mp4 -f null -

# 示例 2：QSV 解码 + 软件编码
ffmpeg -hwaccel qsv -c:v h264_qsv -i input.mp4 -c:v libx264 output.mp4

# 示例 3：QSV 解码 + QSV 编码（全硬件链路）
ffmpeg -hwaccel qsv -c:v h264_qsv -i input.mp4 -c:v hevc_qsv -b:v 5M output.mp4

```

## 无损压缩

- libx265

```shell
ffmpeg -i input.mp4 -c:v libx265 -x265-params lossless=1 -c:a copy output.mp4
```

- hevc_nvenc

```python
ffmpeg_command = [
    'ffmpeg',
    '-hwaccel', 'cuda',  # 启用CUDA硬件加速
    '-hwaccel_output_format', 'cuda',  # 指定硬件加速的输出格式
    '-vcodec', 'h264_cuvid',  # 使用NVIDIA的硬件解码器进行H.264解码
    '-i', input_file,  # 输入文件
    '-vf', 'scale_cuda=1280:720',  # 使用NVIDIA硬件加速进行分辨率缩放
    '-vcodec', 'hevc_nvenc',  # 使用NVIDIA的硬件编码器进行HEVC编码
    '-preset', 'slow',  # 编码预设，较慢的速度通常意味着更好的压缩，提高输出质量
    '-rc', 'vbr',  # 可变比特率控制
    '-cq', '0',  # 设置恒定质量因子为0以启用无损模式
    '-b:v', '0',  # 平均比特率设置为0，因为我们在使用恒定质量模式
    '-acodec', 'copy',  # 音频复制，不转码
    output_file  # 输出文件
]
```
注意在上述脚本中，-cq 0 是用来指定无损模式的，而在hevc_nvenc中，这表示启用无损压缩2。

另外，如果你希望使用HM（HEVC Test Model）工具来进行无损压缩，可以通过命令行参数--TransquantBypassEnable=1和--CUTransquantBypassFlagForce=1来实现


## 需要在画面质量和源视频一样的前提下。尽可能的减小文件大小

```shell
ffmpeg -i A.mp4 \
       -map 0 \
       -c:v libx265 \
       -crf 24 \
       -preset slow \
       -c:a copy \
       A.mkv
```

-crf 24: 这是 最核心的参数。

CRF 代表 Constant Rate Factor (恒定速率因子)。这是一种控制视频质量的模式。它不会去适配某个特定的比特率，而是尝试在整个视频中维持一个恒定的“感知质量”。编码器会根据画面的复杂度动态调整比特率：对于复杂的动态画面（如爆炸、水花），分配更高的比特率；对于静态画面（如风景、对话），分配更低的比特率。

这完美符合你的需求：“保持画面质量”。

对于 libx265，CRF 的取值范围是 0-51，数值越小，质量越高，文件越大。

0 是无损的（但文件巨大，通常没必要）。

~18 通常被认为是视觉上几乎无损的。

22-28 是一个非常常用的范围，能在质量和文件大小之间取得极佳的平衡。24 是一个非常可靠的、质量不错的起点。

-preset slow: 这个参数控制编码速度和压缩效率的平衡。

可用的预设包括 ultrafast, superfast, veryfast, faster, fast, medium (默认), slow, slower, veryslow。

preset 越慢，编码器就会花费越多的时间去分析视频帧，寻找更好的压缩方法。这意味着在 相同的CRF值（即相同的质量）下，使用更慢的 preset 会得到更小的文件。

### 参数解释

#### `-preset`

这个参数用于设置编码的预设，它是一个在速度和质量之间进行权衡的综合设置。数字越小，编码速度越快，但质量可能越差；数字越大，编码速度越慢，但质量通常越好。

  - `p1` (最快) 到 `p7` (最慢)：这是一组渐进的预设，从最快的编码速度（最低质量）到最慢的编码速度（最高质量）。
  - `hq` (High Quality) 和 `hp` (High Performance)：这些是基于质量或性能的旧预设名称。通常 `hq` 提供了更好的视觉质量，而 `hp` 则以更快的速度为代价。
  - `ll` (Low Latency): 用于需要低延迟的应用，例如视频会议或直播。
  - `lossless`: 无损编码，文件会很大，但不会有任何质量损失。
  - `p4` 是默认值，这是一个很好的起点，在速度和质量之间取得了不错的平衡。

**建议：**

  - 对于快速转码或直播，可以尝试 `p1` 或 `p2`。
  - 对于高质量的视频归档，推荐使用 `p5` 或 `p6`，并结合其他质量参数。
  - 如果你是为了进行视频编辑或后处理，需要保留原始画质，可以使用 `lossless`。

#### `-tune`

这个参数用于进一步微调编码器，以适应特定的应用场景。它通常与 `-preset` 结合使用。

  - `hq`: 高质量模式，适用于对视觉质量要求高的场景。
  - `ll`: 低延迟模式，与 `ll` preset 类似，用于直播。
  - `ull`: 超低延迟模式，比 `ll` 更激进。
  - `lossless`: 无损模式。

**注意：** 现代的 `-preset` 参数通常已经包含了大部分的 `tune` 效果，所以在使用时可能不需要显式设置 `tune`。

#### `-profile`

设置 HEVC 编码的配置文件。配置文件定义了编码器可以使用的特性和工具集，以确保播放设备能够正确解码。

  - `main`: 基本的配置文件，支持 8 位色彩深度。
  - `main10`: 支持 10 位色彩深度，可以提供更好的色彩过渡和更少的色带（banding），特别适合处理 HDR 视频。
  - `rext`: Range Extensions，支持更多高级特性，例如更高的位深和 chroma 采样格式。

**建议：**

  - 如果你的源视频是 10 位 HDR，或你希望获得更高的画质，强烈推荐使用 `main10`。

#### `-level`

设置编码的级别（Level）。级别定义了视频的最大分辨率、帧率、码率等约束，以确保视频能在各种硬件上顺利播放。例如，Level 4.0 限制了最大分辨率和码率，而 Level 5.1 允许更高的分辨率（如 4K）。

  - `auto`: 自动选择合适的级别。
  - `1.0` 到 `6.2`: 具体的级别，每个级别都有其对应的最大限制。

**建议：**

  - 通常保持 `auto` 即可，FFmpeg 会根据你的输入视频参数自动选择。如果你需要兼容特定的老旧设备，可能需要手动设置较低的 Level。

#### `-rc` (Rate Control)

控制码率（比特率）的模式，这是影响文件大小和质量的核心参数。

  - `constqp`: Constant Quantization Parameter (恒定 QP)。视频质量恒定，但文件大小会随视频复杂度变化。QP 值越低，质量越高，文件越大。
  - `cbr`: Constant Bitrate (恒定码率)。视频码率恒定，文件大小可预测，但视频质量会随复杂度波动。
  - `vbr`: Variable Bitrate (可变码率)。在给定的平均码率下，编码器会根据视频复杂度动态调整码率，以在保持文件大小可控的同时，尽量保证质量。
  - `vbr_hq` / `cbr_hq`: `hq` 后缀表示高质量模式，通常比普通模式使用更复杂的算法。

**建议：**

  - **追求质量且不关心文件大小波动：** 使用 `-rc constqp`。
  - **追求文件大小可控且对质量有一定要求：** 使用 `-rc vbr`，并配合 `-b:v` (目标码率) 和 `-maxrate`。
  - **直播或流媒体：** 使用 `-rc cbr`，确保码率稳定。

#### `-rc-lookahead`

预编码帧数。编码器在决定如何编码当前帧时，会预先分析后面的帧，从而做出更优的决策。

  - 值为 `0` 表示不启用。值越大，编码效果越好（特别是对于 VBR 模式），但会增加延迟和内存使用。

#### `-2pass`

启用两遍编码。第一遍编码会分析视频，收集信息（如运动矢量、场景复杂度等），生成日志文件。第二遍编码利用这些信息进行更精确的码率分配，通常能获得更好的质量和更小的文件大小。

  - `auto` 是默认值。在使用一些需要两遍编码的 `-preset` (如 `slow`) 时，它会自动启用。
  - 你可以显式设置为 `true` 来强制开启两遍编码。

#### `-gpu`

用于选择使用哪块 NVIDIA GPU 进行编码。

  - `0`: 使用第一块 GPU。
  - `1`: 使用第二块 GPU，以此类推。
  - `any` (`-1`): 使用第一块可用的 GPU。
  - `list` (`-2`): 列出所有可用的 GPU。

**示例：**
如果你想指定使用第二块 GPU 进行编码，你可以这样做：

```bash
ffmpeg -i input.mp4 -c:v hevc_nvenc -gpu 1 -preset p5 -rc vbr -b:v 5M output.mp4
```

#### `-aq-strength`

当启用空间自适应量化（Spatial AQ）时，此参数用于调整其强度。Spatial AQ 可以在视觉上不那么重要的区域（如平滑的背景）使用更高的量化参数，而在细节丰富的区域使用更低的量化参数，从而节省码率，提升感知质量。

  - 值从 `1` (弱) 到 `15` (强)。默认值是 `8`。

#### `-qp` / `-init_qpI` / `-init_qpP` / `-init_qpB`

这些参数用于设置量化参数（QP）。QP 值越低，质量越高，文件越大。

  - `-qp`: 在 `constqp` 模式下设置恒定 QP 值。
  - `-init_qpI` / `-init_qpP` / `-init_qpB`: 分别设置 I、P、B 帧的初始 QP 值。这些值通常在 `-rc vbr` 模式下使用，作为码率控制的参考起点。

### 总结与实践

对于日常转码，一个高质量的命令通常会包含以下几个关键参数：

1.  **`-c:v hevc_nvenc`**: 指定编码器。
2.  **`-preset p5` 或 `p6`**: 在速度和质量之间取得很好的平衡。
3.  **`-rc vbr`**: 采用可变码率模式，可以提供更好的质量。
4.  **`-b:v <目标码率>`**: 设置视频的目标码率，例如 `5M` (5 Mbps)。
5.  **`-maxrate <最大码率>`**: 设置视频的最大码率上限，防止瞬间码率过高，例如 `10M`。
6.  **`-profile main10`**: 如果是 HDR 源或需要 10 位色彩，请务必加上。
7.  **`-gpu 0`**: 如果你有多个 GPU，指定一个来使用。

**示例命令：**

```bash
# 这是一个高质量、文件大小可控的转码命令
ffmpeg -i input.mp4 -c:v hevc_nvenc -preset p6 -rc vbr -b:v 5M -maxrate 10M -profile main10 output.mp4
```
